# dsh 记忆与技能插件 · 架构说明

> 依据 `20260813-dsh记忆与技能插件开发计划-v08.md`，纯插件叠加（不修改 dsh 核心）。

## 一、插件关系

```
dsh (Cordis 插件树)
├── dsh-memory-harness  记忆：MEMORY 持久化 + SOUL 注入 + memory_* 工具 + 档案隔离
├── dsh-skill-forge     技能：写端工具 + staged/promote + 后台 review 三路输出
└── dsh-review-core     共享基建：digest / 去重 / 安全扫描 / review prompt+解析（纯 TS）
    复用 dsh 现成：ctx.skills 读端 / session log / ctx.systemPrompt / ctx.jobs / ctx.llm
```

三个包可独立安装；`dsh-review-core` 为 P2 抽取的公共包（G4 已切共享导入、副本已删除：skill-forge/memory 从 `@dsh-cortex/dsh-review-core` 导入 digest/dedupe/security/prompt）。

## 二、装配（计划 §1.3）

在 profile 的 `package.json` 用 `link:` 依赖 + `dsh.profile.bundles` 追加：

```jsonc
{
  "dependencies": {
    "dsh-memory-harness": "link:/abs/path/dsh-memory-harness",
    "dsh-skill-forge": "link:/abs/path/dsh-skill-forge",
    "dsh-review-core": "link:/abs/path/dsh-review-core"
  },
  "dsh": {
    "profile": {
      "bundles": ["@deepseek-ai/dsh-base", "@deepseek-ai/dsh-headless", "dsh-memory-harness", "dsh-skill-forge"]
    }
  }
}
```

记忆插件须装配在 agent-instructions / tool-skill 之后（注入顺序 baseline→catalog→memory，D15/D21）。

## 五、验证分层

| 层 | 机制 | 执行时机 |
|---|---|---|
| ① 进程内 + mock | vitest + MockAdapter，确定性断言 | 每个里程碑 |

| ③ 真进程引导 | `dsh --profile A/B`、resume | M4 整合验收 |

纯逻辑单测（store/forge/profile/security/digest/dedupe/prompt）已在沙箱内全绿；dsh 依赖文件的完整类型检查与 ①②③④ 在 vendor 进 monorepo 后执行。

## 六、范围边界

- **USER 用户画像**：已启用（store 双槽位 + 快照 USER PROFILE 段 + 面板编辑）；review 三路输出③（userUpdates 应用）待补。
- **review 触发**：v2 定稿为 `cadence`（10 用户轮 / 10 工具迭代节律，checkpoint 增量）+ `session-end`；详见《自动技能化机制设计.md》（实现进行中，v1 的 idle 一次性触发将被替换）。
- **headless one-shot 下 review 不生效（已知非目标）**：review 是 web/长驻特性，headless 一次性任务进程退出太快，后台 review job 无法在退出前完成；如需 headless 触发需装配 `dsh-tool-jobs` 且加「退出前等待后台 job settle」的有界关停，投入产出不成比例——**不做，记为非目标**。
- **pending 审批门控**：D7 取消默认，未实现。
