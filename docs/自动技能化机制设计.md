# 自动技能化机制设计（v2 · 评审定稿）

> 对象：`@dsh-cortex/dsh-skill-forge`（含 `dsh-review-core` 配合）与 `@dsh-cortex/dsh-cortex-ui` 面板侧。
> 定稿：2026-08-16 · 用户审批通过，实现进行中。
> 前置阅读：`docs/架构说明.md`、v08 计划 §5（Review 触发策略）。

---

## 一、背景与问题（v1 实现的三个缺陷）

v1（当前已装配）的 review 机制来自对 Hermes 的一次过度简化，暴露出三个严重问题：

1. **一天只存一次**：`reviewed` 集合按「会话 × 进程生命周期」去重，`idle` 触发后该会话在本进程内永不再 review——服务开一天，每个会话只有第一次空闲时被总结一次，后续全部经验丢失。
2. **触发点不明确**：触发挂在 `agent/status` 空闲事件上，用户无法预期"哪一刻会发生总结"；`session-end` 在 web 长驻形态下几乎永不发生。
3. **去重缺失**：review 输出只会 `forge.create` 新建技能，没有与现有技能目录比对——同一经验重复出现会反复新建，技能库快速膨胀（用户已遭 Hermes 自动保存之苦）。

## 二、Hermes 调研结论（源码：`agent/background_review.py` 等）

| 维度 | Hermes 实际做法 | 依据 |
|---|---|---|
| 触发节奏 | **按轮次节律持续触发**：记忆路每 10 个用户轮（`memory.nudge_interval`），技能路每 10 次工具迭代（`skills.creation_nudge_interval`） | `turn_context.py:593-599`、`turn_finalizer.py:698-704` |
| 触发位置 | 轮次计数在本轮开始/结束时检查；review 在**本轮回复送达后**以 daemon 线程后台执行，不与主任务抢模型 | `turn_finalizer.py:714-724` |
| review 形态 | fork 子 agent（max 16 迭代），工具白名单仅 memory + skill 管理，**主动调工具**落盘；"Nothing to save" 是显式空操作 | `background_review.py:1-17、893-909` |
| 去重 | 无"每会话一次"粗门控；**写入层去重**：review 可见现有目录，优先 patch 已有技能（四级优先：在用技能 → 已有伞技能 → support file → 才新建），memory 工具自带 no-duplicate | `background_review.py:207-244` |
| 计数器存活 | agent 实例字段，resume 按 `prior_user_turns % interval` 恢复——长会话持续沉淀 | `turn_context.py:550-551` |
| 缓存策略 | 同模型 fork 继承 warm cache 全量重放；异模型压缩 digest | `background_review.py:33-43` |
| 写入方式 | **直接写库**（技能库膨胀的根源，本设计不采用） | 同文件首段 |

## 三、目标机制（评审定稿）

### D-a 节律触发（对齐 Hermes，替代"每会话一次"）

- `reviewTrigger` 枚举重构：`'cadence' | 'session-end' | 'off'`，**默认 `'cadence'`**（废弃从未实现的 turn-end/batch）。
- 新增 `reviewTurnInterval`（默认 **10** 用户轮）与 `reviewToolInterval`（默认 **10** 次工具调用）。
- 检查点：`agent/status` 空闲事件（skill-forge 装配在 bundle 根层，可收到全部会话的该事件）时统计**自上次 checkpoint 以来**的增量，任一计数达标 → 调度一次后台 review job（`ctx.jobs`，进行中去重，绝不并发堆叠）。
- 效果：长会话每 10 轮沉淀一次，一天持续产生经验更新；触发条件可预期、可解释（日志记录触发原因 turn/tool）。

### D-b checkpoint 增量（防重启重复、防重复提取）

- 持久化：`$DSH_HOME/pending/review-checkpoints.json`，按 `sessionId` 记录 `{ lastUserTurns, lastEventSeq, lastDigest }`。
- 语义：每次 review 只消费**自 checkpoint 以来的增量轮次**；review 完成后更新 checkpoint。
- web 重启后会话 resume，checkpoint 仍在 → 不重复 review 已处理段落，也不因进程重启重置节律计数。
- 增量过小（例如不足 1 轮或与上次 digest 相同）→ 不触发，零成本。

### D-c 写入层三道去重（对齐 Hermes，替代"只 create"）

1. **同名 → patch 合并**：review 候选技能名已存在于现有目录（ctx.skills）或 staged → 改走 `forge.patch` 合并内容，不新建。
2. **相似跳过**：候选 description 与现有技能相似度 ≥ `dedupeSimilarity`（默认 0.8）→ 跳过（复用 review-core `similarity/isDuplicate`，该能力此前只用于 MEMORY 路）。
3. **no-change 出口**：review prompt 保留"Nothing to save"约定；解析结果为空 → 零写入。
4. MEMORY / USER 路维持既有 isDuplicate + no-change 过滤。

### D-d staged 人控入库（解决"库被搞乱"，Hermes 直接写库不采用）

- 保留 v1 的 staged（扫描根外）+ promote 机制（D3/D19 缓存保护，Hermes 没有，值得保留）。
- 自动入库时机不变：web 重启启动清扫 + 全部会话结束（`session/disposed` 后无 live session）。
- 新增人工通道：面板 skill tab「待入库（staged）」分区，逐项 **入库 / 丢弃**。
- 新增 bridge 路由：`GET /cortex/api/staged`（清单）、`POST /cortex/api/staged/promote {name}`、`POST /cortex/api/staged/discard {name}`（直接操作 `$DSH_HOME/pending/skills-staged`，不依赖插件服务）。
- 自动生成的技能保持既有双重标识：名字 `-auto-save` 后缀 + 描述 `(Auto-save)` 后缀（已实现）。

### D-e review 输入：增量 + 尾窗

- 输入 = **checkpoint 以来的增量轮次** + 最近 8 轮尾部窗口 + 复用会话日志已有 compaction 摘要（review-core `buildConversationDigest` 扩展增量参数）。
- 主模型直跑（digest 成本可控）；`reviewProvider/reviewModel` 可换便宜模型（异模型场景 digest 本就是更优选择，与 Hermes 策略一致）。

### D-g review 形态：Hermes 式 fork 子 agent（优先）+ 单发 JSON（回退）

- **主路径 fork 子 agent**（对齐 Hermes background_review 的 agentic 形式）：
  - 经 `ctx.subagents.start('spawn', ...)` 起进程内子 agent（独立会话、零父上下文）；
  - `toolFilter` 白名单：`memory_add/replace/remove` + `skill_create/patch/edit/delete` + `skill`（读正文；子 agent 无此工具时降级重试纯写白名单）——白名单外的工具在提示词与运行时同时消失；
  - `persona` = review 指令（Hermes 信号分类学 + 受保护技能 + 反向过滤 + `-auto-save`/`(Auto-save)` 强制后缀 + staged 说明），影子化 deployment:persona，仅对子 agent 生效；
  - 首条用户消息 = 增量 digest + 现有技能目录（含 source 标注）；子 agent 自主读库（skill 工具）→ 调工具落盘（共享 store/forge，staged + 人控入库语义不变）；
  - 防递归：子 agent 会话加入 excluded 集合，不参与节律触发；超时 180s（signal 中止 → aborted 记为失败）；
- **回退**：session-end 无 agent 可作 parent 时，退回单发 JSON 路径（runSingleShot）。
- 质量收益：先读后写（不再盲合）、多轮自主决策、可自我修正；成本：1-3 次模型调用。

### D-f 触发与生命周期时序

```
用户轮 N 结束 → agent/status idle
  → 增量计数（用户轮/工具调用）
  → 达标且该会话无进行中 job
  → ctx.jobs 后台调度 review（不阻塞主会话；job 输出技能→staged、MEMORY/USER→store）
  → 完成后更新 checkpoint 文件 + 写日志（触发原因/输出摘要）
用户可在面板 staged 分区随时 入库/丢弃。
```

## 四、配置变更

| 字段 | v1 | v2（定稿） |
|---|---|---|
| `reviewTrigger` | `'session-end' \| 'idle' \| ...` 默认 session-end | `'cadence' \| 'session-end' \| 'off'` 默认 **cadence** |
| `reviewTurnInterval` | —（无） | **10**（用户轮节律，记忆路） |
| `reviewToolInterval` | —（无） | **10**（工具迭代节律，技能路） |
| `reviewRecentTurns` | 8 | 8（尾窗，语义不变） |
| `reviewMinResultChars` / `dedupeSimilarity` | 200 / 0.8 | 不变；dedupeSimilarity 扩用于技能相似跳过 |
| `reviewProvider` / `reviewModel` | ''（不配置不触发） | 保留；本机配置 deepseek-official / deepseek-v4-pro |

> D17 提醒：schema 字段变化 = 安装/升级时一次全量 KV 失效（开发期可接受；上线前不再变更字段名与默认枚举值）。

## 五、缓存与成本

| 项 | 说明 |
|---|---|
| 调用频率 | 每会话每 10 轮一次；job 进行中去重，无并发堆叠；长会话一天约十几次量级 |
| 主会话缓存 | review 是独立请求（system=review prompt），不触碰主会话前缀；主会话跨步缓存零影响 |
| 技能目录消息 | 技能仍走 staged → promote，promote 前的目录消息不变（D19/R1 保护保留） |
| 失败处理 | job 失败只记日志不重试风暴；解析失败丢弃并记日志（沿用 v1） |

## 六、验收清单

1. 长会话连续 30+ 轮 → 日志可见 ≥3 次 review 触发（记录触发原因 turn/tool），而非仅 1 次。
2. 重启 web 后继续同会话 → 不重复 review 已处理段落（checkpoint 生效，检查 review-checkpoints.json）。
3. 同一经验重复出现 → 只产生一个技能（同名 patch 合并 / 相似度跳过）。
4. 面板 staged 分区可见：清单正确，入库后 skills/change 触发目录更新，丢弃后不再出现。
5. 主会话响应延迟与缓存命中不受影响（回归指标 cacheReadTokens/inputTokens）。

## 八、决策记录

| # | 决策 | 理由 |
|---|---|---|
| 1 | 触发改轮次节律，不采用"每会话一次" | 对齐 Hermes 实证；一天长会话必须持续沉淀 |
| 2 | checkpoint 持久化到文件而非进程内存 | web 重启常见，内存计数会重置且导致重复 review |
| 3 | 去重放写入层（同名 patch + 相似跳过 + no-change） | 对齐 Hermes；比粗粒度"reviewed 集合"精准且不丢经验 |
| 4 | 保留 staged/promote，不加 Hermes 式直接写库 | 保护技能目录消息与 KV 前缀（D19/R1）；用户可人控入库，避免库被自动保存搞乱 |
| 5 | 触发检查挂在 agent/status idle | dsh 现有事件面里最接近"一轮结束"的信号；skill-forge 在 bundle 根层可全局收到 |
