# 开发准则（DSH-Cortex）

项目所有代码、文档、提交信息、UI 文案必须遵守以下准则。新增准则时在此追加并注明日期。

## 1. 严禁使用 emoji（2026-08-16）

- 范围：源码、UI 文案、注释、文档、README、提交信息、日志输出、测试断言文案。
- 替代：图标一律使用 dsh 官方 primitives 图标（`@deepseek-ai/dsh-client-ui-primitives`）；纯文本场景用文字描述。
- 例外：无。测试用例中如确需断言含 emoji 的第三方数据，单独说明。

## 2. 自动技能化（review）四项铁律（2026-08-16 · 评审定稿）

依据 Hermes 源码调研与用户评审，`dsh-skill-forge` 的自动总结机制必须遵守（详见 `docs/自动技能化机制设计.md`）：

1. **节律触发，禁止一次性**：按轮次节律持续触发（默认 10 用户轮 / 10 工具迭代），任何"每会话一次"或"每进程一次"的粗门控都违反本准则；计数器与 checkpoint 必须跨 web 重启存活。
2. **增量消费，禁止全量重放**：每次 review 只消费自 checkpoint 以来的增量轮次；review 完成后必须更新 checkpoint（`$DSH_HOME/pending/review-checkpoints.json`）。
3. **写入层去重优先**：技能写入前必须与现有目录（ctx.skills + staged）比对——同名走 patch 合并、描述相似度 ≥0.8 跳过、无变化零写入；禁止绕过目录比对直接 create。
4. **staged 人控入库**：自动生成的技能先入 staged，入库必须经面板人工确认或会话边界自动 promote；禁止 Hermes 式绕过 staged 直接写扫描根（保护技能目录消息与 KV 前缀）。
